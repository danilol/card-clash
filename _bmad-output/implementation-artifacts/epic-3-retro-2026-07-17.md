## What went well

- **Speed (Danilo's headline):** "with the automated implementation I got the speed I want… it was awesome." The automation exists so he can maintain multiple projects at the same time — and this epic showed the quality gates keep working at that speed.
- **The pre-dev spec-validation pass (new this epic) earned a permanent place.** It caught defects before any code existed: a missing `zod` server dependency and an ESLint-duplication trap (3.1); a genuine UX bug — the second-person "Opponent left — you win" label headed for the third-person public list — plus a live-socket-in-jsdom trap and first-`vi.mock` gotchas (3.2).
- **The adversarial review is load-bearing under D23.** The 3.1 implementation shipped a real crash vector (pg pool with no 'error' listener → a Postgres restart would kill the whole game server); the review caught it pre-merge. 14 patches total across both stories; dismissals were evidence-backed.
- **Debt discipline:** `deferred-work.md` items landed exactly in the stories that had claimed them.

## What was bumpy

- One flaky test run (3.1, right after formatting; never reproduced in 5 consecutive clean runs). Unexplained, noted in the story's debug log.
- A lint fix quietly changed CardView's art-retry behavior — in scope, but a reminder that hygiene fixes can smuggle behavior changes; the auditor's "worth a human glance" flag was the right instinct.
- Structural honesty: implementer and review-orchestrator are the same model now. The independent review layers performed well, but they are essential infrastructure, not garnish. Never merge without them.

## Key lessons

1. **Keep the pipeline exactly as it ran this epic:** approved spec → fresh-context spec validation → TDD → live smoke → 3-layer adversarial review → merge. Each stage caught something the others could not.
2. **Cheapest-stage defect removal works:** the spec validator fixed bugs for the cost of a paragraph that would have cost a rework cycle after implementation.
3. **Behavior changes riding along with hygiene fixes deserve an explicit call-out** in completion notes (CardView case) so a human can glance at them.
