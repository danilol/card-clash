## What went well

- **Incremental delivery quality** (Danilo's highlight): each story shipped a visibly working slice; the epic never needed a big-bang integration.
- **The learning goal worked:** Danilo went in new to Express/Socket.IO and hand-built the whole server/client through 2.5.
- **playerId ≠ token seam (2.2)** quietly enabled token identity (2.4), forfeit lookup (2.6), and the future reconnect.
- **Pure-helper pattern** (`buildStartViews`, `resolveDisconnect`) kept socket logic unit-testable without live sockets.
- **Quality trend up:** 2.1/2.2 had binding violations in review; from 2.3 on, all ACs passed with only small findings.
- **D23 pilot (2.6) succeeded:** TDD (red→green), 12 new tests, automated socket-level smoke replacing two-tab manual checks, 3-layer review, merge — from a one-line feature request.

## What was bumpy

- **Invisible errors — the bug class of the epic (TOP lesson).** Four stories had an error state the player couldn't see: stuck "connecting" (2.1), leaked ZodError shape (2.2), stored-but-never-rendered `match:error` (2.4), stale error on the result screen (2.6). Root theme: error state existed; rendering it was forgotten.
- **`match:state` (socket event) vs `match/state` (reducer action)** naming trap bit in 2.3, 2.4, and 2.5.
- **Client DOM test infra (jsdom + Testing Library) was deferred in every story 2.3 → 2.6 and never landed.** All component behavior is still manually verified.
- **Scope incident (2.5):** card artwork shipped against FR29's "no artwork"; resolved by amending FR29 rather than reverting. Fine outcome, but the guard fired late.

## Key lessons

1. **Every error state needs a visible rendering and a test.** Add this as an explicit checklist line in story specs and review prompts.
2. **Action items need an owner who will actually execute.** Under D23 that owner is the AI for anything code-shaped.
3. **Deferring the same item 4 stories in a row means "schedule it now."** The client test infra is the example; it lands at the start of Epic 3.
4. **The D23 flow works.** Keep the approval gate on story specs; keep the 3-layer review before merge.
