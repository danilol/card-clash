## What went well

- **The working agreement held end to end.** Every story: branch → Danilo hand-writes → AI writes tests → green → review → fix → merge. Never broke down.
- **"Decide before coding" (Task 1) paid off every story** — stat directions (1.4), trump-id routing (1.5), pot order (1.6), result shape (1.7), PlayerView shape (1.8). Front-loading the hard choices kept implementations clean.
- **Strong invariant testing** — multiset conservation on every state change, plus the seeded random-play property test (1.7) proving matches always terminate with 32 cards intact.
- **Tight scope via `deferred-work.md`** — deferrals were conscious and each landed in the right later story (tie throw → 1.6; match-end/`shift()!` guard → 1.7).
- **Review caught real bugs before merge** — notably 1.7's round-cap-with-equal-stacks throwing instead of going to sudden death (AC2 violation), and 1.5's type-tightening.

## What was bumpy

- **Early-story clarity (TOP lesson).** The first stories' specs were too high-level and used too-native English; Danilo (non-native speaker) had to ask for simpler language mid-story. Clarity matters most in the foundational stories — this should have been right from story 1.
- **Recurring hygiene-miss class** — missing/unused imports (1.4, 1.5, 1.8) and dead code (1.6, 1.7), caught in review every time but recurring. No linter is configured to catch this class automatically.
- **Stale completion notes vs. code** (1.6) — notes described the opposite of the code; took a couple of cycles to reconcile.
- **1.6 (ties/pot) needed several design rounds** — genuinely the hardest story; handled well but iterative.

## Key lessons

1. **Write specs in simple English from story 1** — short sentences, common words, define each term on first use, concrete examples over abstract prose. (Reinforces the standing "write simple English" preference; the failure was drifting from it early.)
2. **Keep the Task-1 "decisions before coding" pattern** — it works; formalize it for Epic 2.
3. **Automate the hygiene class** — a linter for unused imports / dead code would catch the recurring misses before review (a lint rule was flagged as far back as the 1.2 review and is still open).

## Epic 2 readiness — critical path (from `deferred-work.md`)

Epic 2 ("Play It": Express + Socket.IO server + React client wrapping the engine) needs these **before** the server can import the engine at runtime:

- 🔴 **Engine build/packaging (the #1 blocker, story 2.1).** `package.json` `exports`/`main`/`types` point at `./src/index.ts`; Node cannot load `.ts` from `node_modules`. Repoint to `dist/`, add a build script, and add `tsconfig.build.json` or `exclude` so test files are not emitted into `dist`.
- 🟡 Root typecheck uses `--if-present` (a package with no typecheck script passes vacuously). Ensure the new server/client packages ship a `typecheck` script; consider dropping `--if-present`.
- 🟡 `skipLibCheck` decision before adding Express / Socket.IO / React type deps.
- 🟡 Linter for unused imports / dead code (action item 3) — best added early in Epic 2.
- 🟢 zod validation at the wire boundary (2.2) enforces the 2-player / non-empty shape the engine currently trusts — this closes the standing `find()!` / `shift()!` deferral.
